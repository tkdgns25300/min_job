## 개요

- **프로젝트명**: MinJob (민잡) — ministry + job
- **한 줄 설명**: 흩어진 부교역자 청빙 공고를 모아 구조화·비교하게 해주는 채용 플랫폼
- **타겟 교단**: 예장합동 · 예장통합
- **타겟 사용자**: 사역지를 구하는 부교역자(부목사·전도사), 청빙하는 교회
- **수익 모델**: 등록 무료 + 프리미엄 노출 유료 (교회 측 과금)
- **타겟 시장**: 한국

## 배경 (왜 이 제품인가 — 핵심만)

청빙 정보가 여러 신학교 게시판·교단 게시판·청빙넷 등에 흩어져 있어, 구직 교역자는 여러 사이트를 순회해야 한다. 기존 사이트들은 2000년대식 게시판이라 검색·필터·비교가 빈약하고, 공고가 자유 텍스트라 조건 비교가 안 된다. 청빙넷이 이미 "모아보기"를 표방하므로, MinJob의 차별점은 단순 수집이 아니라 **① 구조화(필터·정렬·비교) ② 신뢰 정보(재공고 추적) ③ 교회 정보 연결(홈페이지·유튜브 링크)**이다.

**스코프 — 부교역자 청빙만 다룬다.** 담임목사 청빙은 노회 승인·공동의회 결의·청빙위원회·보안 유지 등 무거운 공식 절차가 얽혀 민감하고 웹 플랫폼 개입 여지가 적어 제외한다.

> ⚠️ 사용자 니즈는 구직 전도사 1명(개발자 누나) 인터뷰 기반 **가설**이다. 운영하며 검증·갱신한다.

## 사용자 모델 (3역할)

| 역할 | 설명 | 주요 행위 |
|---|---|---|
| **구직자(seeker)** | 사역지를 찾는 부교역자 | 공고 검색·필터·열람, (Phase 3) 프로필 등록 |
| **교회(church)** | 청빙하는 교회 담당자 | 공고 등록·관리, 운영자 등록 공고 claim, 프리미엄 노출 결제 |
| **운영자(admin)** | 본인(개발자) | 수집 공고 AI 구조화·등록, claim 승인, 전체 관리 |

- 구직자는 **로그인 없이도 공고 열람 가능**(공개). 프로필 등록 등은 로그인 필요.
- 초기 공고는 운영자가 manual seeding으로 채운다('운영자 등록'). 교회는 나중에 claim으로 자기 공고를 가져간다.

## 핵심 기능

### 1. 공고 목록 (`/jobs`)

구직자의 진입점. "여기부터 본다"가 되게 하는 핵심 화면.

- **공고 카드**: 교회명·교단·지역 / 직분·부서·고용형태 / 사례비(있으면) / 게시일 / 프리미엄 배지·재공고 배지
- **검색**: 교회명·제목·지역 텍스트
- **필터**: 교단 · 지역 · 직분 · 부서 · 고용형태 · 사례비 범위
- **정렬**: 최신순(기본) / 사례비 / 마감 임박. 프리미엄 공고 상단 고정
- **상태**: 모집 중 공고만 기본 노출
- 필터·정렬 상태는 URL params로 유지(뒤로가기 복원)

### 2. 공고 상세 (`/jobs/[id]`)

- **구조화 정보**: 교단·지역·직분·부서·고용형태·사례비·출근요일·제출서류·자격요건
- **교회 정보 연결** (★ 핵심 페인 해결): 교회 홈페이지·유튜브 링크를 상세에서 바로 클릭 (따로 검색할 필요 없음)
- **재공고 정보** (Phase 2): "이 교회는 최근 N개월간 이 자리를 M번 공고"
- **지원 안내**: 교회 연락처 또는 "원문 보기"(원문 링크)로 안내. 사이트 내 지원 중개는 Phase 3
- **SEO**: JobPosting JSON-LD

### 3. 교회 상세 (`/churches/[id]`)

- 교회 기본 정보 + 홈페이지·유튜브 링크
- 그 교회의 현재/과거 공고 목록 → 재공고 패턴 가시화

### 4. 공고 등록 — 교회용 (`/jobs/new`, 로그인 필요)

- 공고 필드를 채우는 등록 폼 (교단·지역·직분·부서·고용형태·사례비·출근요일·서류·홈페이지·유튜브 등 — 필드 정의는 DATA.md)
- 등록 자체는 **무료**
- 등록 시 '교회 직접 등록'으로 기록, 본인이 소유자

### 5. 소유권 인수 — claim (`/claim`, 로그인 필요)

- 교회가 "내 교회로 등록된 공고가 있나요?" 검색 (교회 단위로 claim → 그 교회의 공고가 함께 따라온다)
- 해당 교회 선택 → claim 신청 → 운영자 승인 후 소유권 연결
- 이후 교회가 직접 공고 수정·재등록·관리 가능

### 6. 운영자 도구 — admin (`/admin/**`, 운영자 전용)

- **수집 공고 등록 도구(`/admin/ingest`)**: 사람이 공개 게시판에서 확보한 공고 텍스트를 붙여넣으면 → AI가 교회·공고 필드 자동 구조화 → 폼에 채워짐 → 검토 후 등록('운영자 등록', 소유자 없음). ★ 자동 크롤러 아님(가드레일 #1)
- **공고 관리(`/admin/jobs`)**: 전체 공고 CRUD, 상태 변경
- **claim 승인**: 교회의 인수 신청 검토·승인

### 7. 프리미엄 노출 (수익화)

- 기본 등록 무료, **상단 고정·강조·추천 배지**를 유료 옵션으로 (프리미엄 노출 플래그)
- 과금 주체는 교회. 결제 연동은 추후 Phase에서 (초기엔 수동 처리 가능)

### 8. 마이페이지 (`/mypage`, 로그인 필요)

- 교회: 내 공고 목록·관리, claim 상태
- 구직자: (Phase 3) 저장한 공고, 프로필

### 9. 향후 기능 (Phase 3)

- **인재 DB(링크드인형)**: 구직자가 프로필 등록 → 교회가 먼저 연락. 기존 게시판이 전부 단방향이라 비어 있는 영역
- 사이트 내 지원·서류 중개
- 공고 끌어올림/재등록 편의

## 비즈니스 규칙

- **등록 무료, 노출 유료**: 공고 등록에 과금하지 않는다. 프리미엄 노출(상단·강조)만 유료.
- **과금 주체는 교회**: 구직자는 전부 무료(사람을 모으기 위함).
- **claim 승인 조건**: 운영자가 신청자가 해당 교회 관계자인지 확인 후 승인(초기 수동).
- **공고 출처 표기**: 운영자가 등록한 공고는 "원문 보기" 링크 제공, 교회가 claim하면 출처가 교회로 전환.

## 비기능 요구

- **검색 응답**: 필터·검색 결과가 빠르게(체감 지연 최소). 공고 목록은 캐시 서빙.
- **데이터 정직성**: 사례비 등 비정형 표현은 왜곡 없이 원문 보존(필드 설계는 DATA.md). 공고 본문 원문 통째 복제 금지(요약·구조화).
- **개인정보**: 연락처 등 민감 정보 취급 시 동의·처리방침 (정책은 DATA.md).
- (UI 규칙·모바일 퍼스트는 CLAUDE.md Styling.)

## 우선순위 (개요 — 작업 단위는 ROADMAP.md)

- **Phase 1 (MVP)**: 공고 목록·상세·검색·필터, 교회 홈페이지·유튜브 링크, 교회 공고 등록 폼, admin 수집·구조화 등록 도구, 인증
- **Phase 2 (차별화)**: 재공고 추적, 거리 기반 필터, 소유권 인수(claim), 프리미엄 노출
- **Phase 3 (고도화)**: 인재 DB, 사이트 내 지원 중개, 끌어올림, 결제 연동

## 디자인 방향

- 깔끔하고 신뢰감 있는 톤. 기존 청빙 사이트의 구식 게시판과 대비되는 **현대적 UI**가 차별화의 일부.
- 공고 카드가 한눈에 비교되도록 정보 위계를 명확히 — 작은 화면에서도 핵심 조건이 바로 읽히게.
- 구조화된 정보(교단·지역·사례비·부서)를 배지·라벨로 시각화해 "비교 가능함"을 체감하게.
