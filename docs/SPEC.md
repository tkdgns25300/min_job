> 페이지·기능·역할 명세. 데이터 모델은 [`DATA.md`](./DATA.md), 아키텍처·컨벤션은 [`../CLAUDE.md`](../CLAUDE.md), 작업은 [`ROADMAP.md`](./ROADMAP.md).

## 개요

- **프로젝트명**: MinJob (민잡) — ministry + job
- **한 줄 설명**: 흩어진 교회 사역자 청빙 공고를 모아 구조화·비교하게 해주는 채용 플랫폼
- **타겟 시장**: 한국 개신교(기독교) 교역자 청빙 전반 — 특정 교단에 한정하지 않는다
- **초기 집중 거점(beachhead)**: 예장합동·예장통합 (신학교 커뮤니티 접근성 + 개발자 인맥). **시장은 넓게, 초기 공고 확보·마케팅은 한 거점에 집중**
- **타겟 사용자**: 사역지를 구하는 교회 사역자(부목사·전도사 중심, 담임목사 포함), 청빙하는 교회
- **수익 모델**: 등록 무료 + 프리미엄 노출 유료 (교회 측 과금)

## 배경 (왜 이 제품인가 — 핵심만)

청빙 정보가 여러 신학교 게시판·교단 게시판·청빙넷 등에 흩어져 있어, 구직 교역자는 여러 사이트를 순회해야 한다. 기존 사이트들은 2000년대식 게시판이라 검색·필터·비교가 빈약하고, 공고가 자유 텍스트라 조건 비교가 안 된다. 청빙넷이 이미 "모아보기"를 표방하므로, MinJob의 차별점은 단순 수집이 아니라 **① 구조화(필터·정렬·비교) ② 신뢰 정보(재공고 추적) ③ 교회 정보 연결(홈페이지·유튜브 링크)**이다.

**스코프 — 교회 사역자 청빙을 다룬다. 주력은 부교역자(부목사·전도사).** 담임목사 청빙은 노회 승인·공동의회 결의·청빙위원회 등 무거운 공식 절차가 얽혀 초기 물량은 적을 것으로 보이나, 실수요가 있어 **직분 옵션으로 포함**한다 (타겟 인터뷰 2026-07-02, [`INTERVIEWS.md`](./INTERVIEWS.md)).

> ⚠️ 사용자 니즈는 구직 전도사 1명(개발자 누나) 인터뷰 기반 **가설**이다. 운영하며 검증·갱신한다.

## 사용자 모델 (단일 계정 + 역할 view)

**계정은 하나.** 모든 계정은 기본 **사역자(MINISTER)** — 로그인만으로 검색·북마크·관심 교회 이용. **교회 인증**(증빙 서류 + 운영자 승인) 통과 시 같은 계정에 **교회(CHURCH) view**가 열려 자기 교회 공고를 관리한다. **"교회 전용 계정"은 없다**(교회는 엔티티, 사람 계정은 관리 자격). 데이터 모델 = DATA §3·§4.

| view/역할 | 누구 | 주요 행위 | 개방 조건 |
|---|---|---|---|
| **사역자(MINISTER)** | 모든 로그인 계정(기본) | 공고 검색·열람(비로그인도) · 북마크 · 관심 교회 · 재공고 알림 | 로그인 |
| **교회(CHURCH)** | 인증된 교회 담당자 | 자기 교회 공고 등록·관리, 노출 결제 | 교회 인증 승인 |
| **운영자(admin)** | 본인(개발자) | 수집 공고 구조화·등록, 공고/교회 인증 검수 | allowlist |

- **가입 시 역할 선택 없음** — 로그인=사역자, 교회는 인증으로 승격(단일 정체성). 부교역자가 **구직 중이면서 자기 교회 공고 관리**도 가능(흔한 케이스).
- 구직자(사역자)는 **로그인 없이도 공고 열람**. 로그인 시 **북마크(Phase 1)** · 관심 교회·알림(Phase 2).
- **공고 소유 = 교회 엔티티**(가드레일 #2). 담당자는 관리 자격 — 편집 권한 = 그 교회 인증 관리자. 이동/다중 담당자는 DATA §3.
- 초기 공고는 운영자 manual seeding('운영자 등록', owner 없음). 인증 교회가 **클레임**해 자기 교회 공고로 관리(운영자 등록 공고와 병존).

## 핵심 기능 — 접근 영역별

> 표준 채용 사이트(잡코리아·원티드·사람인) 공통 요소 중 **1인 운영 + "지원은 교회 연락처로 직접" 모델에 맞는 가벼운 것만** 채택. 이력서 DB·사이트 내 지원·포지션 제안 같은 무거운 양면 거래는 Phase 3로 미룬다.

### A. 공개 영역 (로그인 불필요) — 트래픽 핵심

- **홈 (`/`)**: 검색 + 스탯(모집 중·새 공고) + 추천 청빙(AD) + 최신 공고 — 상세는 아래 "페이지별 섹션(확정)"
- **공고 목록 (`/jobs`)**: 검색·필터(교단·지역·직분·부서·고용형태·사례비)·정렬. 구직자 메인 화면
- **공고 상세 (`/jobs/[id]`)**: 구조화 정보 + 교회 홈페이지·유튜브 링크(★ 핵심 페인 해결) + 재공고 정보 + 지원 안내(원문 보기 / 교회 홈페이지 — 사이트 내 지원 없음) + JobPosting JSON-LD
- **교회 상세 (`/churches/[id]`)**: 교회 정보(사진 갤러리·위치·채널) + 그 교회 공고·재공고 이력(패턴 가시화). 공고 상세에서 진입 — **교회 목록(browse)은 두지 않음**(구직자는 공고를 검색하지 교회를 훑지 않음; `/jobs` 교단·지역 필터가 대체, 리뷰·연봉 같은 enrichment도 없어 값 약함. 향후 필요 시 "교회 검색" 형태로만)
- **소개 (`/about`)**: 서비스 소개·신뢰 구축
- **공고 노출 안내 (`/pricing`)**: 노출 상품 안내(교회 대상). **top nav 아님** — footer + 교회 여정 맥락(공고 등록/관리·AD 섹션). (내용은 아래 "수익화" 섹션)
- **약관·개인정보처리방침 (`/terms`, `/privacy`)**: 로그인·개인정보를 다루므로 **필수**
- **문의**: 푸터 `mailto` (초기엔 폼 X — 스팸·운영 부담)

### B. 인증 영역 (로그인 필요) — 단일 계정, 인증으로 교회 view 개방

- **로그인 (`/login`)**: 간편 로그인 **카카오·네이버·구글** + 이메일. **가입 시 역할 선택 없음**(로그인=사역자). 전용 미니멀 레이아웃(박스 없음). 상세 = 아래 "로그인" 블록
- **교회 인증** (`/mypage`에서 진입): 교회 선택/생성 + 증빙 서류(고유번호증/사업자등록증) 업로드 → 운영자 승인. 승인 후 교회 view·공고 게재 활성. 미인증 상태로 공고 등록 시도 시 인증 유도
- **공고 등록·수정 (`/jobs/new`, `/jobs/[id]/edit`)**: **교회 인증 관리자만**(게이트). '교회 직접 등록'. 편집 권한 = 그 교회 인증 관리자(owner 일치 아님). 등록 **무료**
- **마이페이지 (`/mypage`)** — 계정 상태별 (상세 = "마이페이지" 블록):
  - **사역자 view**(기본): 최근 본 공고 · **북마크(Phase 1)** · 관심 교회·재공고 알림(Phase 2)
  - **교회 view**(인증 승인 시): 내 교회 공고 관리 + 요약 + 새 공고 등록 + 운영자 공고 클레임 + 교회정보. 헤더 view 토글
  - 미인증/검수중/반려 상태별 게이트 UI
- **(선택) 관심 조건 알림** (Phase 3): 표준 기능이나 알림 발송·운영 부담이 커 후순위

### C. 운영자 영역 (admin — 최소 형태로 유지)

거창한 시스템 ❌, **공고 입력 작업대**로만:

- **공고 등록 도구 (`/admin/ingest`)**: 수집한 공고 텍스트 붙여넣기 → AI가 교회·공고 필드 자동 구조화 → 검토 후 등록('운영자 등록', 소유자 없음). 운영자 핵심 작업 화면. ★ 자동 크롤러 아님(가드레일 #1)
- **공고 관리 (`/admin/jobs`)**: 등록 공고 수정·삭제·상태 변경
- → 대시보드·통계·교회관리 등 별도 admin 시스템은 **만들지 않는다**

## 수익화 — 광고·노출 (첫 매출 채널)

등록은 무료, **노출이 유료**. 교회가 결제하면 공고를 "더 많이·더 크게·눈에 띄는 위치"에 보여준다.

- **노출 등급**: 일반 / 프리미엄(목록 상단 고정 + 강조 배지) / 대표 광고(홈·목록 상단 추천 슬롯에 더 크게)
- **노출 위치·크기·기간 차등**: 요금에 따라 노출 위치·카드 크기·노출 기간을 다르게. 기간 만료 시 자동 강등
- **정렬 반영**: 프리미엄·대표 광고가 정렬에서 우선(정렬·필터 규칙 표 참조)
- 결제는 초기엔 수동 처리, 자동 결제 연동은 Phase 3

> **노출 상품은 2종(프리미엄·대표광고)으로 진행**한다. 끌어올리기(bump)·강조 add-on은 공고량이 적고 단순성이 니치의 무기라 **제외**(공고량 늘면 재검토). **가격은 앵커로 공개**(프리미엄 7만원/주·대표광고 15만원/주, 주 단위·4주 묶음 할인)하되 **결제만 "문의"** — 초기엔 무료·할인 시딩(정가는 내리긴 쉬워도 올리긴 어려움). 실단가·부가세·최종 확정은 Phase 2, 라이브 결제·구좌 예약 없음. *사용자 노출 라벨 = **"공고 노출 안내"**.* 배너 광고(기독 B2B)는 Phase 2+ 옵션. **수익 모델 5종·노출 레버 7종·조사 근거 상세 = SNAPSHOT §9.**

## 의도적으로 안 하는 것 (스코프 보호)

- **사이트 내 지원·이력서 DB·포지션 제안** → Phase 3. 무거운 양면 거래라 1인 운영 제약과 충돌. 초기엔 "지원은 교회 연락처로 직접".
- **교회 리뷰·평점** → 하지 않음. 좁은 기독교 공동체에서 명예훼손·분쟁 리스크가 큼. "신뢰 정보"는 재공고 추적 같은 **객관 데이터로만** 제공.
- **거대 admin 대시보드·통계** → 안 함(1인 운영).

## 비즈니스 규칙

- **등록 무료, 노출 유료**: 공고 등록에 과금하지 않는다. 프리미엄·대표광고 노출만 유료.
- **과금 주체는 교회**: 구직자는 전부 무료(사람을 모으기 위함).
- **공고 출처 표기**: 운영자가 등록한 공고는 "원문 보기" 링크를 제공한다. 교회가 직접 등록한 공고는 그 교회가 관리한다.

## 비기능 요구

- **검색 응답**: 필터·검색 결과가 빠르게(체감 지연 최소). 공고 목록은 캐시 서빙.
- **데이터 정직성**: 사례비 등 비정형 표현은 왜곡 없이 원문 보존(필드 설계는 DATA.md). 공고 본문 원문 통째 복제 금지(요약·구조화).
- **개인정보**: 로그인·간편 로그인·북마크·알림으로 개인정보를 처리하는 순간 **약관·개인정보처리방침·수집이용 동의가 법적으로 필수**(로그인 기능과 동시에 갖춘다). 정책은 DATA.md.
- (UI 규칙·모바일 퍼스트는 CLAUDE.md Styling.)

## 우선순위 (개요 — 작업 단위는 ROADMAP.md)

- **Phase 1 (MVP)**: 공개 열람(홈·목록·상세·교회) + 검색·필터, 로그인(단일 계정)·마이페이지·**북마크**, 교회 인증·공고 등록·수정, admin(ingest+jobs+인증 승인), 소개·약관·개인정보·문의
- **Phase 2 (차별화)**: 재공고 추적, 거리 기반 필터(지도 임베드), 광고·노출(프리미엄·대표광고), 관심 교회 팔로우·재공고 알림, 사후 신고
- **Phase 3 (고도화)**: 인재 DB, 사이트 내 지원 중개, 결제 연동(자동 과금), 공고 재등록 편의, 관심 조건 알림, 검색광고
