고유번호를 확인하면 나머지 항목이 열려요.

확인 버튼은 명시적입니다. 10자리를 채우면 자동 조회하는 방식은 오타로 10자리가 됐을 때 "처음 등록"으로 판정돼 칸이 펼쳐지고, 고치면 다시 접히며 깜빡입니다. 버튼은 사용자가 확인 의사를 밝히므로 상태 전환이 예측 가능하고 서버 호출도 통제됩니다(사업자번호 확인이 업계 관례이기도 합니다).
확인 전에는 제출이 잠깁니다 — 신규인지 기존인지가 정해지지 않으면 무엇을 저장할지 알 수 없습니다. 직접 POST로 건너뛰어도 서버가 같은 조회를 다시 하므로 안전합니다.
입력 중 숫자만 남습니다. 123-45-67890을 붙여넣어도 1234567890이 되고 10자리에서 끊깁니다 — 하이픈이 섞이면 UNIQUE가 무의미해지기 때문입니다.

담당자 확인을 위해 증빙 서류와 사무용 연락처가 필요해요.

교회명 하나만 보여줍니다. 교단·지역·주소까지 채워 보여주면 ① 사용자가 고칠 수 있다고 오해하고(미승인자는 인증된 교회 값을 덮어쓸 수 없습니다) ② 우리가 가진 교회 정보를 로그인한 아무에게나 노출합니다. 이름은 "이 교회 맞나요?" 확인 용도로만 필요합니다.
검증 상태(미검증·인증 완료)는 알려주지 않습니다 — "등록되어 있다"까지입니다. 그 이상은 운영자 판단이고 사용자가 알 필요가 없습니다.
버려지는 입력이 0이 됩니다 — 기존 교회면 그 칸을 보여주지도 않습니다.
